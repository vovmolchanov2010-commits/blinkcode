# 1. Маршрут до друга в live-режиме

**Приоритет:** P0 · **Фаза:** MVP · **Оценка:** 4–5 чн

## Суть

Построить маршрут не до статичной точки, а до друга, который сам движется. Маршрут и ETA пересчитываются по мере перемещения обоих.

## Пользовательские истории

- Как пользователь, я хочу нажать «Дойти до Вити» и получить маршрут, который сам обновляется, если Витя ушёл из кафе в парк.
- Как пользователь, я хочу видеть, сколько мне осталось идти/ехать до друга.
- Как друг, к которому идут, я хочу видеть, что Маша идёт ко мне и будет через 7 минут — и не уходить далеко.
- Как пользователь, я хочу вариант **«встретиться посередине»**, чтобы никто не шёл весь путь в одиночку.

## Основной сценарий

1. Пользователь открывает профиль друга на карте → «Построить маршрут».
2. Если друг делится геолокацией с пониженной точностью — запрос: «Маша хочет к тебе прийти. Показать точную геолокацию на 1 час?» (по умолчанию — разрешено для «близких друзей», см. приватность).
3. Выбор режима: пешком / общественный транспорт / авто / самокат.
4. На карте — маршрут, ETA, расстояние, «хвост» перемещения друга.
5. Друг получает уведомление «Маша идёт к тебе, будет через ~12 мин» и может ответить быстрым статусом («жду у входа», «я внутри»).
6. Когда расстояние < 50 м — режим «рядом»: стрелка-компас + вибрация, маршрут скрывается.
7. Сессия завершается автоматически при встрече или через 1 час.

## Критерии приёмки

- [ ] Маршрут перестраивается, если цель сместилась > 100 м от исходной точки маршрута **или** пользователь сошёл с маршрута > 50 м.
- [ ] Перестроение не чаще 1 раза в 15 с (защита API-квоты и батареи).
- [ ] ETA обновляется не реже раза в 30 с во время активной сессии.
- [ ] Друг видит, кто к нему идёт и ETA; может отключить точную геолокацию — тогда маршрут ведёт к последней известной точке с пометкой «данные устарели N мин назад».
- [ ] «Встретиться посередине» предлагает точку (кафе/метро/площадь) примерно на равном **времени** пути для обоих, а не на равном расстоянии.
- [ ] Работает при свёрнутом приложении (фоновые обновления + постоянное уведомление на Android / Live Activity на iOS).
- [ ] Сессия гарантированно закрывается через 60 мин, точная геолокация возвращается к обычной точности.

## Техническая реализация

- **Частота геолокации в активной сессии:** у обоих участников повышается до 1 обновления / 3–5 с; вне сессии — обычный адаптивный режим (см. [architecture](../architecture.md#батарея-и-частота-геолокации)).
- **Доставка позиций:** WebSocket-канал `route_session:{id}`; сервер пересылает позицию цели инициатору и наоборот.
- **Маршрутизация:** провайдер маршрутов (Mapbox Directions / Яндекс Маршрутизация / 2ГИС / свой Valhalla — зависит от рынка). Перестроение на клиенте по правилам выше; запрос идёт через наш бэкенд (кэш, квоты, смена провайдера без релиза).
- **Встреча посередине:** берём 3–5 кандидатов из базы POI вблизи геометрической середины, считаем матрицу времени (Matrix API) для обоих и выбираем минимум `max(t1, t2)`.
- **Сущность:** `route_sessions(id, requester_id, target_id, mode, status, started_at, expires_at)`.

## Ограничения и риски

| Риск | Что делаем |
|---|---|
| Стоимость Directions API при частых перестроениях | Пороги перестроения, кэш, батчинг, self-hosted движок при росте |
| Батарея у обоих участников | Повышенная частота только в сессии и с таймаутом 60 мин |
| Сталкинг: «идти к человеку, который этого не хочет» | Цель всегда видит, кто к ней идёт; может остановить сессию одним тапом; работает только для взаимных друзей |
| Плохой GPS в помещениях / метро | Показываем точность (радиус) и «данные устарели», не рисуем ложный маршрут |

## Метрики

- Доля сессий маршрута, закончившихся встречей (расстояние < 50 м).
- Среднее число перестроений на сессию, стоимость API на сессию.
- Доля сессий, остановленных целью (сигнал о дискомфорте).

## MVP / потом

- **MVP:** пешком + авто, live-пересчёт, ETA для обоих, авто-завершение.
- **Потом:** общественный транспорт, «встретиться посередине», режим «компас» в радиусе 50 м, AR-стрелка.
