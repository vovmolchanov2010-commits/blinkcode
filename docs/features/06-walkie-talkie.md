# 6. Режим рации

**Приоритет:** P2 · **Фаза:** v1.2 · **Оценка:** 6–8 чн

## Суть

Вместо звонка или чата — рация для группы друзей, которые собираются в одном месте. Зажал кнопку — все участники группы в радиусе 500 м слышат короткое голосовое (до 10 секунд).

## Пользовательские истории

- Как участник сбора, я хочу крикнуть «мы у второго входа!» всем, кто рядом, не открывая чат.
- Как участник, я хочу, чтобы сообщения воспроизводились сами, пока включён режим рации.
- Как участник, я хочу выключить рацию, если сейчас неудобно слушать.

## Кто слышит сообщение

**Только участники той же группы/сбора, у которых включён режим рации, и которые находятся в радиусе 500 м.** Никаких незнакомцев поблизости — иначе это канал для спама и харассмента.

## Основной сценарий

1. В карточке сбора (фича 2) или группы → «Рация» (включается на время сбора, авто-выключение через 3 часа).
2. Большая кнопка: зажал — запись (до 10 с), отпустил — отправка.
3. Получатели в радиусе слышат сообщение автоматически (если рация включена) с коротким сигналом «пип» и именем отправителя на экране.
4. Если получатель вне радиуса или рация выключена — сообщение попадает в чат сбора как обычное голосовое (не теряется).
5. Индикатор: «Тебя услышат 4 человека» до отправки.

## Критерии приёмки

- [ ] Длительность ≤ 10 с, запись обрывается автоматически.
- [ ] Задержка от отпускания кнопки до начала воспроизведения у получателя: p50 ≤ 1.5 с, p95 ≤ 3 с при нормальной сети.
- [ ] Автовоспроизведение работает при заблокированном экране (iOS — через PushToTalk framework, Android — foreground service).
- [ ] Радиус проверяется на сервере по последним позициям (свежесть позиции ≤ 60 с); участники без свежей позиции получают сообщение в чат, а не в эфир.
- [ ] Рация не включается без явного действия пользователя и сама выключается по таймауту.
- [ ] Перед отправкой видно число получателей.

## Техническая реализация

**Вариант 1 (MVP) — store-and-forward:**
запись на устройстве → кодек Opus ~16–24 кбит/с (10 с ≈ 20–30 КБ) → загрузка в хранилище → сервер вычисляет получателей (геозапрос по Redis GEO) → push/WebSocket → автоплей.

**Вариант 2 (потом) — потоковое аудио:**
WebRTC SFU (например, LiveKit) — воспроизведение начинается во время записи, задержка < 500 мс. Сложнее, дороже, но настоящий «эффект рации».

**Платформенные особенности:**

| | iOS | Android |
|---|---|---|
| Фоновое воспроизведение | **PushToTalk framework** (iOS 16+) — официальный путь: системный UI, push типа `pushtotalk`, автоплей на заблокированном экране | Foreground service (тип `microphone`/`mediaPlayback`) + high-priority FCM |
| Ограничения | Нужен PTT-entitlement, канал один на приложение в моменте | Ограничения на запуск FGS из фона (Android 12+), нужен корректный тип сервиса |

## Ограничения и риски

| Риск | Что делаем |
|---|---|
| Ограничения ОС на фоновый звук | PushToTalk на iOS, FGS на Android; ранний технический спайк (2 чн) до коммита в роадмап |
| Внезапный звук в неподходящий момент | Только явное включение, авто-выключение, системный индикатор |
| Неточная геолокация → «не тот радиус» | Буфер +100 м к радиусу и фолбэк в чат |
| Записи с посторонними | Хранение 24 ч, потом удаление |

## Метрики

- Доля сборов, где использовалась рация.
- Сообщений рации на сбор; доля воспроизведённых автоматически.
- p50/p95 задержка доставки.

## MVP / потом

- **v1.2:** store-and-forward, только внутри сбора, iOS PushToTalk + Android FGS, фолбэк в чат.
- **Потом:** потоковое аудио (WebRTC), постоянные «каналы» для групп, настраиваемый радиус, транскрипция в текст для тех, кто не может слушать.
