# 3. Чекины и исследование районов (геймификация)

**Приоритет:** P1 · **Фаза:** v1.1 · **Оценка:** 6–8 чн

## Суть

Превратить чекины в игру: показывать, сколько процентов своего района пользователь исследовал, где бывает чаще всего, и соревноваться с друзьями — «кто открыл больше новых мест за месяц».

## Пользовательские истории

- Как пользователь, я хочу видеть «туман войны» на карте и как он рассеивается там, где я побывал.
- Как пользователь, я хочу знать: «Ты исследовал 37% Басманного района».
- Как пользователь, я хочу видеть свои «места силы» — где я бываю чаще всего.
- Как пользователь, я хочу месячный рейтинг среди друзей по новым местам.
- Как пользователь, я хочу делать ручной чекин в конкретном месте (кафе, парк) с фото/эмодзи.

## Две механики

| | Пассивное исследование | Ручной чекин |
|---|---|---|
| Что это | Автоматически отмечаем ячейки карты, где был пользователь | Пользователь сам отмечается в месте (POI) |
| Даёт | % района, «туман войны», новые ячейки | Историю мест, «места силы», лента друзей |
| Включение | Opt-in, требует фоновой геолокации | Всегда доступно |

## Основной сценарий

1. Онбординг фичи: «Открой свой город» → объяснение + включение пассивного исследования.
2. Слой «Исследование» на карте: туман войны, открытые ячейки подсвечены.
3. Экран прогресса: текущий район (%), топ районов, «новых мест за месяц», «места силы» (топ-5 по времени пребывания).
4. Рейтинг друзей за месяц: новые ячейки + новые чекины; сброс 1-го числа.
5. Достижения: «Первые 10% района», «Ночной исследователь», «10 парков» и т.п.

## Критерии приёмки

- [ ] Район определяется по административным границам (OSM `admin_level`, для Москвы — районы/муниципальные округа).
- [ ] % района = открытые ячейки / все ячейки района (без воды и закрытых территорий — v1.2).
- [ ] Ячейка засчитывается, если пользователь был в ней ≥ 1 мин или прошёл насквозь пешком (скорость < 15 км/ч). На транспорте — не засчитываем (иначе из окна метро/такси «открывается» город).
- [ ] «Места силы» видны **только самому пользователю** по умолчанию; зона «дом» исключена из любых публичных данных.
- [ ] Рейтинг друзей показывает только числа, без карт перемещений.
- [ ] Защита от накрутки: детект mock-location, проверка правдоподобной скорости между точками, лимит открытых ячеек в час.

## Техническая реализация

- **Сетка:** [H3](https://h3geo.org/) — разрешение 9 (~0.1 км², ребро ~170 м) для исследования; разрешение 7–8 для агрегатов/тепловой карты.
- **Храним только ячейки, а не треки:** `explored_cells(user_id, h3_index, first_seen_at, visits)`. Трек используется на устройстве/сервере для вычисления и удаляется.
- **Районы:** предрасчёт `district_cells(district_id, h3_index)` из полигонов OSM (полифилл H3). Прогресс считается инкрементально.
- **БД:** PostgreSQL + PostGIS + расширение `h3-pg`.
- **Чекины:** `checkins(id, user_id, place_id, created_at, photo_url?, emoji?, visibility)`.
- **Рейтинги:** материализованное представление / Redis sorted set `leaderboard:{month}:{friend_graph}` — считаем по запросу для списка друзей (их мало), глобальные рейтинги не делаем в v1.

## Ограничения и риски

| Риск | Что делаем |
|---|---|
| Тепловая карта «где был чаще всего» раскрывает дом/работу | Приватно по умолчанию, исключение зон дом/работа, только агрегаты для друзей |
| Батарея при пассивном исследовании | Используем существующий фоновый поток геолокации, не повышаем частоту |
| Накрутка через GPS-спуфинг | Детект mock-провайдера (Android), проверки скорости, ручная модерация топа |
| Скучно после «открытия» своего района | Сезонные цели, новые районы, достижения, челленджи (фича 4) |

## Метрики

- Доля пользователей, включивших исследование.
- Открытых ячеек на пользователя в неделю.
- Просмотры рейтинга друзей; рост retention у включивших исследование vs контроль.

## MVP / потом

- **v1.1:** туман войны, % района, ручные чекины, месячный рейтинг друзей, 10–15 достижений.
- **Потом:** «места силы» с тепловой картой, сезонные события, командные зачёты (компания друзей vs компания), карта города целиком.
